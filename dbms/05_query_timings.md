# Query timings

Baseline timings for every query in `04_queries.sql`, taken on the schema from `03_schema.sql` without any changes to indexes or queries.

## Setup

- Date: 2026-11-23
- PostgreSQL: 18.4 (Postgres.app)
- Machine: Darwin arm64
- Data: generated by `tools/seed_bulk.sql`, followed by `VACUUM ANALYZE`

## Method

- Each query ran 3 times with `EXPLAIN (ANALYZE, BUFFERS)`, each time in a new psql session.
- The query is prepared and executed with real values taken from the data (listed below).
- Write queries run inside a transaction that is rolled back, so every run sees the same data. Queries that need a certain state (W7, W8, W19) run a small setup statement first, shown at the top of their plan file.
- The time is the `Execution Time` that PostgreSQL reports. It leaves out network time and Node.js time.
- Run 1 can be slower than runs 2 and 3 because the data may not be in cache yet.
- Scan type lists the table scan nodes in the plan of run 1. The full plans are in `plans/<id>.txt`.

Values used for the parameters: `uid=1 rated=171 rider=1 ev=122 ev_busy=1 pend_req=60010 pend_ride=10 appr_req=10 done_ride=1 w9_ride=10 notif=60000`
